# Данные выборов в Государственную Думу 2026

Архив открытых данных по выборам депутатов Государственной Думы Федерального Собрания Российской Федерации девятого созыва. Период голосования: **18–20 сентября 2026 года**.

Источник данных: публичные страницы и ответы сайта [izbirkom.ru](http://izbirkom.ru/). Снимок сформирован 22 сентября 2026 года. Идентификатор выборов в источнике: `587813923`.

В репозитории оставлены только итоговые структурированные выгрузки. Сырой HTTP-кэш, журналы запросов, промежуточные файлы, настройки загрузчика и служебная статистика не включены.

## Как скачать данные самостоятельно

Нужен Python 3.10 или новее и доступ к публичному сайту избиркома. Дополнительные библиотеки устанавливать не требуется. Скачайте репозиторий, откройте терминал в его папке и запустите:

```bash
python download.py
```

В Windows можно дважды щёлкнуть `RUN_WINDOWS.cmd`; окно покажет итог и не закроется сразу после завершения. Если команда `python` недоступна в терминале Windows, используйте `py -3 download.py`. Скрипт одинаков для ПК, ноутбука, Windows, Linux и macOS. По умолчанию он обходит выборы в Госдуму 18–20 сентября 2026 года (`587813923`): комиссии, опубликованные протоколы, сведения о кандидатах и партиях. Финансовые отчёты не запрашиваются. Параллельная загрузка включена; стандартное число потоков по комиссиям — 16.

Если после запуска видно `[СТАРТ]`, но долго нет списка выборов, скрипт ждёт доступ к API сайта. Таймаут одного сетевого запроса по умолчанию — 90 секунд, затем возможны повторы. Сообщения `[СЕТЬ]` покажут причину и номер повтора. В такой ситуации проверьте, открывается ли сайт с этого компьютера и не мешает ли прокси; процесс можно остановить и позднее запустить снова.

Сначала для короткой проверки можно запустить:

```bash
python download.py --test-limit 2
```

Тестовый запуск обрабатывает ограниченное число комиссий и карточек. Для полной выгрузки после него запустите обычную команду без `--test-limit`. Если загрузку прервали, повторите ту же команду: сохранённые ответы используются повторно. Скрипт сохраняет каждый полученный ответ отдельным файлом в `download/izbirkom_2026-09-18_20/raw/`, а итоговые таблицы — в `exports/`. Полный обход может создать сотни тысяч файлов и занять много часов; точное число зависит от ответов источника. Содержимое `data/` — уже опубликованный снимок, поэтому новая загрузка складывается отдельно.

На слабом соединении или при ошибках сервера уменьшите параллелизм, например:

```bash
python download.py --commission-workers 8 --delay 0.1
```

Для всех параметров запустите `python download.py --help`. По умолчанию запрашиваются этапы `reports,candidates`; финансовый этап и вложенные PDF/DOCX/XLSX не запускаются. Папка `download/` исключена из Git: она останется на компьютере запускающего и не появится в GitHub сама по себе.

## Формат

Файлы используют **JSON Lines (JSONL), UTF-8**: каждая строка — отдельный JSON-объект. Это позволяет обрабатывать данные построчно и не загружать весь файл в память.

Самая большая таблица разбита на 12 gzip-частей по 100 000 строк (последняя часть короче), потому что исходный `result_rows.jsonl` весит около 700 МБ и превышает лимит одного файла GitHub. Сжатие не меняет содержимое строк.

### Пример чтения результатов в Python

```python
import gzip
import json
from pathlib import Path

for path in sorted(Path("data").glob("result_rows.part-*.jsonl.gz")):
    with gzip.open(path, "rt", encoding="utf-8") as file:
        for line in file:
            row = json.loads(line)
            # row["commissionClassifierId"] — комиссия
            # row["infoText"] — кандидат, партия или название показателя
            # row["value"] — числовое значение
```

### Пример чтения в DuckDB

DuckDB умеет читать gzip напрямую:

```sql
SELECT *
FROM read_json_auto(
  'data/result_rows.part-*.jsonl.gz',
  format = 'newline_delimited',
  union_by_name = true
);
```

Например, поиск строк по фамилии:

```sql
SELECT commissionClassifierId, protocolNum, infoText, value, percentValue
FROM read_json_auto(
  'data/result_rows.part-*.jsonl.gz',
  format = 'newline_delimited',
  union_by_name = true
)
WHERE lower(infoText) LIKE '%туманов%';
```

## Как связывать таблицы

- `electionId` связывает все таблицы с выборами.
- `commissionClassifierId` в результатах соответствует классификатору комиссии; `parentCommissionClassifierId` указывает на вышестоящую комиссию.
- `protocolId` и `protocolNum` определяют протокол и его форму.
- `infoText` содержит название показателя, партии или ФИО кандидата.
- `value` — значение строки протокола, `percentValue` — опубликованный процент, если он есть.
- `associationId` связывает регистрационную запись кандидата с избирательным объединением.

## Важные оговорки

- Одна строка в `candidates.jsonl` — регистрационная запись, а не обязательно уникальный человек. Один кандидат может встречаться несколько раз, например в партийном списке и одномандатном округе.
- `result_rows` содержит строки протоколов разных уровней: УИК, территориальные и вышестоящие комиссии. Для анализа голосования по участкам необходимо фильтровать нужный уровень комиссии, иначе агрегаты могут быть посчитаны повторно.
- Названия и значения сохранены в том виде, в котором их опубликовал источник. Возможны отсутствующие поля, разные варианты написания и исправленные протоколы.
- Репозиторий не утверждает собственные права на исходные государственные данные. При повторном использовании следует учитывать правила источника и применимое законодательство.
